## Verified facts about the current code

- `src/utils/orbitControls.js` `BrainOrbitControls` rotates the **specimen** (`orientGroup.quaternion`), not the camera. `update()` slerps `orientGroup.quaternion` toward `this.targetQuaternion` with `rotationSmoothing` 55 (near-instant). A programmatic move must be a separate eased tween (about 1.2 s), not a change to `rotationSmoothing`.
- `_onPointerDown` already copies the current orientation into `targetQuaternion`. Drag-cancel hooks in here without changing drag behavior.
- Axes: +x is the specimen's anatomical LEFT, +y superior, +z anterior (see `src/data/viewsTaxonomy.json`).
- `src/data/brainRegions.json` is the artist handoff and is **never edited**. 20 regions, ids 1 to 20. Broca's (6) and Wernicke's (13) are left-only.
- `src/data/regionGeometry.json` is generated by `scripts/generate-region-geometry.py`. Has per-region `centroid`, `anchor`, `meanX`, plus `labelsPerView` (visible region ids with `visibleFraction` per standard view).
- **Gap:** for bilateral regions the centroid averages both hemispheres, so it sits near the midline. Facing a lateral region (for example 11, Primary Auditory Cortex) from that centroid points the wrong way. M1 step 0 adds per-hemisphere centroids.
- Medial regions (10 Precuneus, 16 Cingulate) face the midline; no exterior view shows them squarely. They get fixed views plus a spoken caveat.
- `agent/` folder is untracked. Commit it first (it holds the agent contract).

## Tool contract (must match the ElevenLabs agent exactly)

Every scene command returns `{ ok: boolean, did: string, reason: string }`. Never claim success that did not happen.

| Command (JS) | Agent tool | Params |
|---|---|---|
| `faceRegion(regionId, { hemisphere })` | `face_region` | `region_id` int 1-20, `hemisphere` optional `left`/`right` |
| `rotateTo(view)` | `rotate_to_view` | `view` one of `left_lateral, right_lateral, anterior, posterior, superior, inferior` |
| `highlightRegion(regionId)` | `highlight_region` | `region_id` |
| `clearHighlight()` | `clear_highlight` | none |
| `setColourRegions(enabled)` | `set_colour_regions` | `enabled` bool |
| `setAnnotations(enabled)` | `set_annotations` | `enabled` bool |
| `lookupRegion({ regionId, name })` | `lookup_region` | returns `{ ok, region: { id, name, division, hemisphere, subtitle, description, factoid } }` (`description` comes from `clickDescription`) |
| `listRegions()` | `list_regions` | returns `{ ok, divisions: [{ name, regions: [[id, name], ...] }] }` |
| `getSceneState()` | `get_scene_state` | returns `{ ok, view, viewExact, visibleRegions, highlightedRegion, colourRegions, annotations, mode }` |

Commands that move the brain resolve **after** the move completes (so the agent speaks about what is now visible). If the user grabs the brain mid-move, they resolve `ok: false` with a truthful reason.

## M1 test list

Write these first. Run them and confirm the new ones fail. R1 to R3 should pass from the start (they guard existing behavior). Commit. Stop for Kyle's review before implementing.

**Regression guards**
- R1: the full existing suite passes with no edits to existing tests.
- R2: with no command ever issued, `update()` produces the same orientation as before.
- R3: after regenerating `regionGeometry.json`, all pre-existing fields are byte-identical; only new fields are added.

**0. Geometry**
- Every bilateral region gets `centroidLeft` (x > 0) and `centroidRight` (x < 0).
- Regions 6 and 13 get `centroidLeft` only.

**A. Orientation math (pure)**

"Facing" means facing the viewer on screen, not world +x. Camera direction is `normalize(camera.position - target)`, read from the live controller (never a hard-coded angle), so the tests hold if the camera moves. Screen-up is `camera.up` made perpendicular to the camera direction.

1. For each of the 6 views, the view's anatomical axis rotated by the specimen quaternion has a dot product > 0.99 with the camera direction. `left_lateral` shows +x.
2. "Up" is screen-up, not world +y. Lateral, anterior and posterior views (and facing a lateral region) keep superior toward screen-up, never upside down. Superior and inferior views put anterior toward screen-up, the anatomy-plate convention.

**B. Programmatic move in `BrainOrbitControls`**
3. A move reaches the target orientation (angle < 0.01 rad) in about 1.2 s, eased (not linear, not instant).
4. A completed move resolves `{ completed: true }`.
5. Pointerdown mid-move cancels instantly: resolves `{ completed: false, reason: 'user' }`; orientation stays where the user grabbed it.
6. A move pauses auto-rotate only for its duration and never alters auto-rotate behavior for a non-voice user. Scroll-zoom does not cancel a move.

**C. Scene commands**
7. `faceRegion(6)` faces the left hemisphere. `faceRegion(6, { hemisphere: 'right' })` still faces left, `ok: true`, and `did` explains it exists only on the left.
8. `faceRegion(99)` returns `ok: false` with the valid range in `reason`.
9. Medial regions (10, 16) use their fixed views; `did` notes the medial surface.
10. A user grab mid-`faceRegion` resolves `ok: false` truthfully.
11. `rotateTo('sideways')` returns `ok: false` listing the 6 valid views.
12. Highlight and clear work. Colour and annotations accept `true`, `false`, `"true"`, `"false"` (port the Atlas normalizer from `docs/reference/atlas/voiceClientTools.js`).
13. `getSceneState` returns the nearest standard view plus `viewExact`, both classified with the same camera-relative measure as A1; `visibleRegions` come from `labelsPerView` for that view. The untouched home view reports `left_lateral` with `viewExact: false` (the camera sits about 11 degrees above level).
14. `lookupRegion({ regionId: 6 })` returns the exact shape; `{ name: "broca's area" }` resolves to 6; `{ name: 'the little brain' }` resolves to 19 (subtitle match); unknown returns `ok: false`.
15. `listRegions()` matches `brainRegions.json` divisions and ids exactly.
16. Drift: the `# My regions` block in `agent/architect-brief.md` matches `brainRegions.json` ids and names exactly.

## Decisions already made

- Scroll-zoom does not cancel a move.
- Wrong hemisphere corrects, does not fail.
- Move duration about 1.2 s; tune by feel later.
- Scene commands take a scene adapter so they test without WebGL.
- Copy Atlas modules, do not extract a shared package.

## Atlas lessons (do not repeat)

- Tools returned "updated" even when nothing happened. Ours report truth.
- Agent id was exposed to the client. Ours: server-minted conversation token only (M3).
- Webhooks unauthenticated. Ours: shared secret (M3).
- App never told the agent what the user did. Ours: contextual updates (M4).
- Prompt, model and voice lived only in the dashboard. Ours: versioned in `agent/`.
